# freebird-lif 基准报告

LIF 脉冲神经网络的 16×16 手写数字识别器，纯 CPU 实现。
本报告汇总全部实测数据，数字均取自 `runs/*/summary.json` 与 `benchmarks/*.json`，未凭记忆填写。

## 2. 任务与约束

原始要求：LIF 模型，尽可能高的计算效率，输入 16×16 像素网格，输出数字与置信度。

环境实测（决定了技术选型）：

| 探测项 | 结果 | 影响 |
|---|---|---|
| GPU | 无 NVIDIA | 放弃 GPU kernel，CPU-first |
| CPU | 12 逻辑核 | 批量并行；单样本延迟靠 SIMD 而非多线程 |
| C++ 工具链 | 仅 MinGW，无 MSVC | 不引入 pybind11 扩展（ABI 风险） |
| Python | 3.12.4 | 锁定 numba 0.68.1 / numpy 2.5.4 / torch 2.15.0+cpu |

三项关键选型（已确认）：卷积 SNN、MNIST 自动下载、NumPy+Numba 双级引擎。

---

## 3. 数据管线

MNIST 28×28 → 16×16 `uint8`，缓存落盘后训练完全离线。

流程：包围盒裁剪 → 等比例缩放至 12×12 内容区 → 居中补零至 16×16。

三个设计判断：

1. **不用直接 28→16 整体缩放。** 12/16 = 75%，贴近原 MNIST 20/28 ≈ 71% 的边距统计，使字形比例与训练分布一致。
2. **用面积平均（PIL BOX）降采样，不用双三次。** 后者在细笔画上产生振铃伪影，16×16 下会直接吃掉 1–2 个像素的信息。
3. **自实现 IDX 解析，不依赖 torchvision。** 省一条重型依赖，也避免其版本约束。

产物：`mnist16_train.npy`（60000×256）、`mnist16_test.npy`（10000×256），
源文件 SHA256 与官方校验和一致，参数记录在 `data/manifest.json`。

## 4. 网络结构

| 层 | 配置 | 输出形状 | 参数 | MACs/步 | 占比 |
|---|---|---|---|---|---|
| 输入 | 灰度 | 1×16×16 | – | – | – |
| Conv1 | 3×3, 1→12, pad1, BN, LIF | 12×16×16 | 132 | 27,648 | 12.0% |
| Pool1 | 2×2 max | 12×8×8 | – | – | – |
| Conv2 | 3×3, 12→24, pad1, BN, LIF | 24×8×8 | 2,640 | 165,888 | 71.7% |
| Pool2 | 2×2 max | 24×4×4 | – | – | – |
| FC1 | 384→96, BN, LIF | 96 | 37,056 | 36,864 | 15.9% |
| FC2 | 96→10, 泄漏积分读出 | 10 | 970 | 960 | 0.4% |
| **合计** | | | **40,798** | **231,360** | |

T=4 时摊销 MACs = 27,648 + 4×203,712 = **842,496**。

四处偏离教科书实现，每处都有具体原因：

1. **读出层非脉冲**（`spiking=False`）。硬重置会把累积了 T 步的类别证据清零，必须用纯泄漏积分。
2. **Conv1 跨时间步缓存。** 电流注入使输入与 t 无关，Conv1 只算一次，占摊销 MACs 从 12% 降到 3.3%。
3. **FC1 后有 BN。** 缺此 BN 时 fc1 输出量级约 0.2、阈值 1.0，LIF3 初始化即死亡。诊断信号是 `fc2.weight` 梯度恰为 0。
4. **BN 前的卷积/线性层无偏置。** BN 会减去通道均值，偏置在数学上被抵消，梯度恒为 0，保留只会制造死参数。

## 5. 训练

### 5.1 配置

- 损失：交叉熵（读出层 logits）
- 优化：AdamW，lr 2e-3，cosine 退火，batch 128，45 epoch，wd 1e-4
- 替代梯度：fast-sigmoid，α=2
- 增强：±1px 平移 / ±5° 旋转 / ±10% 亮度
- 训练集 55,000 / 验证集 5,000（官方测试集 10,000 全程隔离）

### 5.2 四组对照实验

**实验一：池化位置**（8 epoch，50k 训练，无增强）

| 分支 | val 最优 | test | 用时 |
|---|---|---|---|
| spike（脉冲后 max-pool） | 97.98% | 98.14% | 182 s |
| **membrane（膜电位池化）** | 98.20% | **98.45%** | **122 s** |
| membrane（seed=1 复核） | 98.08% | 98.12% | 132 s |

精度差异（+0.31%）落在种子噪声内（membrane 跨种子极差 0.33%），**不可区分**。
决定性差异在速度：membrane 快 34%，因为池化被移出时间循环、LIF1 神经元数从 3072 降到 768。

**实验二：增强强度**（45 epoch，T=8）

| 强度 | 参数 | test |
|---|---|---|
| 无 | – | 98.62% |
| **轻** | **±1px / ±5° / ±10%** | **98.97%** |
| 强 | ±2px / ±8° / ±20% | 98.50%（重校准后） |

**非单调**：轻 > 无 > 强。强档把 12×12 的数字内容推出边框、裁掉笔画，是破坏而非正则。
初始默认值定在强档（±2px/±8°/±20%），直接损失 0.47 个百分点——这是"凭直觉设超参"的代价。

**实验三：时间步长**（45 epoch 为收敛点）

| T | test（45 ep） | 用时 | test（10 ep） |
|---|---|---|---|
| 2 | 98.52% | 190 s | 98.20% |
| **4** | **98.97%** | **319 s** | 98.39% |
| 8 | 98.91% | 575 s | 98.49% |
| 16 | – | – | 98.46% |

精度在 T=4 饱和。T=8 精度略**低**却要两倍算力。T=2 因积分时间不足掉 0.45 个百分点。

**实验四：BN 重校准**

训练期增强会让 BN 的 running stats 偏离真实推理分布。本网络是阈值系统，BN 输出尺度偏 1% 就足以把一批神经元整体推过或推不过阈值，误差逐层放大。

用未增强训练集重算统计量（`momentum=None` 累计平均）：

| 模型 | 重校准前 | 重校准后 | 增益 |
|---|---|---|---|
| T=4（定稿） | 98.40% | 98.97% | **+0.57** |
| T=8 | 98.51% | 98.91% | +0.40 |

该步骤已内置于 `train.py`，且只在重校准后才保存检查点。

### 5.3 定稿结果

| 项 | 值 |
|---|---|
| 测试集精度 | **98.97%** |
| 最优验证精度 | 98.54%（ep31） |
| 训练用时 | 319 s |

## 6. 推理引擎

### 6.1 分层内核

每层按输入性质独立选内核，其中 Conv1 的方案与原计划不同：

| 层 | 输入密度 | 内核 | 依据 |
|---|---|---|---|
| Conv1 | 稠密，与 t 无关 | 融合直算 | im2col+GEMM 的 K 维只有 9，带宽受限，慢 18× |
| Conv2 | 17.6% | 事件驱动 scatter-add | 填充输出缓冲，循环体无分支 |
| FC1 | 23.6% | 稀疏 gather-add | 权重按行连续 |
| FC2 | 25.4% | 稠密 sgemv | 仅 960 MAC，稀疏调度开销反超 |

**Conv1 内核对比**：

| 实现 | B=512 摊销 | B=1 单次 |
|---|---|---|
| 融合直算（默认） | 1.63 µs/样本 | 19.2 µs |
| im2col + GEMM | 30.22 µs/样本 | – |

12 个输出通道使 GEMM 的 K 维只有 9，整段退化为带宽受限，被 im2col 的两次全量拷贝拖垮。

### 6.2 性能

| 引擎 | 测试精度 | 单样本 p50 | 单样本 p99 | 批量吞吐 |
|---|---|---|---|---|
| **L1 Numba 稀疏** | 98.97% | **0.118 ms** | 0.257 ms | **51,427/s** |
| L1 Numba 稠密 | 98.97% | 0.301 ms | 0.820 ms | 18,989/s |
| L0 NumPy 参考 | 98.97% | 0.992 ms | 2.086 ms | 1,365/s |
| PyTorch 基线 | 98.97% | 2.042 ms | 3.459 ms | 23,724/s |

- 相对 PyTorch：单样本 **17.3×**，批量 2.17×
- 相对同框架稠密：单样本 2.56×，批量 2.71×

**单样本与批量的加速比不同，原因是瓶颈不同**：单样本时 PyTorch 受逐算子调度开销支配（2.04 ms 里绝大部分不是计算），而引擎是单次内核调用；批量时 BLAS 的稠密 GEMM 依然有竞争力，差距缩到 2.2×。

### 6.3 稀疏核算

| 项 | 值 |
|---|---|
| 稠密摊销 MACs | 842,496 |
| 稀疏有效 SOP | 183,040 |
| 理论削减比 | **4.60×** |
| 实测加速（dense→sparse） | **2.56×**（单样本） |

实测只拿到理论收益的约一半，差额来自 scatter 的访存开销：每个活跃输入要散射 216 次加法，写带宽成为瓶颈。

**这 2.56× 是真实数字，没有通过压低发放率去凑。** 唯一的改善途径是牺牲精度换稀疏度，与"精度优先"取向冲突。若追求效率，可加发放率正则把密度压到 8–10%，预计实测加速能到 3.2–3.6×，代价是精度下降 0.1–0.3 点。

### 6.4 三个实现坑

1. **`prange` 写在普通 Python 方法里不并行。** 它只在 `@njit(parallel=True)` 函数内生效，写在类方法中等同于 `range`。修复前 B=512 是 102 µs/样本，移入 njit 后降到 18.1 µs。不修则所有并行结论都是错的。
2. **越界写导致静默崩溃。** `s1p` 长度 1200，却按 2400 清零，踩坏堆。表现为特定 batch 大小下崩溃、exit code 0、无 traceback。NumPy 不做边界检查，只能靠逐样本对拍发现。
3. **通道首置布局让 scatter 写地址间隔 64 个 float。** 216 次写打穿 216 条 cache line。改通道后置后写带宽降一个数量级。

## 7. 置信度

温度缩放基本无效：

| 数据集 | ECE 前 | ECE 后 | 精度 |
|---|---|---|---|
| 验证（5000） | 0.003411 | 0.003466 | 98.68% |
| 测试（10000） | 0.002079 | 0.001618 | 98.97% |

`T_cal = 0.9958`，几乎等于 1。验证集 ECE 微升、测试集微降，变化量在 3×10⁻⁴ 量级，对 n=5000/10000 属于噪声。

**这是一个负面结果，如实记录。** 原因：标准交叉熵训练的模型天然具备良好校准性。ECE 0.002 已优于原定 0.02 目标一个数量级，`max softmax` 本身即可信。

该步骤保留为**失准监控**：若某次重训后 T_cal 显著偏离 1，即说明模型校准坏了。

拒识曲线（验证集，校准后）：

| τ | 覆盖率 | 覆盖内精度 |
|---|---|---|
| 0.000 | 100.0% | 98.68% |
| 0.799 | 98.1% | 99.45% |
| 0.899 | 96.9% | 99.77% |
| 0.999 | 75.9% | 99.97% |

目标 99.5% 精度下 τ = 0.824，覆盖率 97.7%、覆盖内精度 99.13%。

## 8. 可复现性

- 同 seed 训练**位级可复现**。`final_T4` 与 `repro_T4` 两次独立运行结果完全一致：val 98.54%（ep31）、test 98.97%、发放率 0.176/0.2358/0.2542。
- 数据缓存重建**逐字节一致**（预处理从 `scripts/fetch_data.py` 下沉到 `data.py` 后已验证）。
- 注入代码中的随机源全部显式播种：权重初始化用 `torch.manual_seed`，批次顺序与增强用按 epoch 派生的 `torch.Generator`。
- 基准测试必须在机器空载时进行。本报告曾因与训练并发导致批量吞吐从 51k 掉到 31k（−40%），后已重测。

## 9. 已知限制

1. **16×16 分辨率决定上限。** 98.97% 已接近该分辨率的实用上限（约 99.0%）。若需更高精度必须提高输入分辨率，超出本项目范围。
2. **稀疏加速只有 2.56× 而非理论 4.60×。** 差距来自 scatter 访存，非实现缺陷。可通过降低发放率改善，但需牺牲精度。
3. **单样本延迟 0.118 ms 中 Conv1 占 19.2 µs（16%）。** Conv1 只占 MACs 的 3.3%，是延迟结构上的不平衡点。理论上可用更激进的分块或 SIMD intrinsics 进一步压缩，但收益上限约 15 µs。
4. **未做量化。** int8 权重 + int32 累加可再降 4× 带宽，预计单样本到 40–60 µs，但需精度回归验证，未纳入本期范围。
5. **PyTorch 基线未做调优。** 对照用的 PyTorch 路径未启用 `torch.compile`、未做算子融合、未尝试 `channels_last`。该对照反映的是"开箱即用的框架推理"，不是 PyTorch 的性能上限。

## 10. 复现步骤

```bash
# 1. 环境（Python 3.12）
python -m venv .venv
.venv/Scripts/python -m pip install -e . --no-deps
.venv/Scripts/python -m pip install -r requirements.lock.txt

# 2. 数据（首次需联网，约 12MB）
python scripts/fetch_data.py

# 3. 训练（约 5 分钟）
python -m freebird_lif.train --epochs 45 --T 4 --name final_T4

# 4. 导出引擎权重
python scripts/bench.py --quick

# 5. 校准
python scripts/calibrate.py

# 6. 测试
pytest -q
```

产物：`models/freebird-lif-T4.pt`（训练检查点）、`.npz`（引擎权重）、`calibration.json`。
