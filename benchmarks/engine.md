# 推理引擎基准

- 平台：Intel64 Family 6 Model 151 Stepping 2, GenuineIntel / Windows / Python 3.12.4
- 模型：`freebird-lif-T4.pt`，T=4，参数 40798
- 样本：10000 条官方测试集；单样本延迟取 1000 次重复的 p50/p99
- 批量吞吐：4096 条重复 8 次取均值

## 精度复核

| 引擎 | 测试精度 |
|---|---|
| L1-numba-sparse | 0.9897 |
| L1-numba-dense | 0.9897 |
| L0-numpy | 0.9897 |

## 单样本延迟（B=1）

| 引擎 | p50 | p99 |
|---|---|---|
| L1-numba-sparse | 0.118 ms | 0.257 ms |
| L1-numba-dense | 0.301 ms | 0.820 ms |
| L0-numpy | 0.992 ms | 2.086 ms |
| PyTorch | 2.042 ms | 3.459 ms |

## 批量吞吐

| 引擎 | 总耗时 | 样本/秒 |
|---|---|---|
| L1-numba-sparse | 80 ms | 51,427 |
| L1-numba-dense | 216 ms | 18,989 |
| L0-numpy | 3000 ms | 1,365 |
| PyTorch | 173 ms | 23,724 |

PyTorch 基线走稠密路径（无稀疏、无 BN 折叠、逐算子调度）。单样本延迟差距 18× 主要来自逐算子调度开销，批量吞吐差距仅 2×——大 batch 下 BLAS 的稠密 GEMM 依然有竞争力。

## 有效算力

| 项 | 值 |
|---|---|
| 稠密摊销 MACs/样本 | 842,496 |
| 稀疏有效 SOP/样本 | 183,039 |
| 理论削减比 | 4.60× |
| 实测加速（同框架 dense→sparse） | 2.56× |

发放率：lif1 0.176 / lif2 0.236 / lif3 0.254
平均活跃输入数：Conv2 135/768，FC1 91/384

## Conv1 内核对比（与 t 无关，每样本只算一次）

| 实现 | B=512 摊销 | B=1 单次 |
|---|---|---|
| 融合直算（默认） | 1.63 µs/样本 | 19.2 µs |
| im2col + GEMM | 30.22 µs/样本 | – |

12 个输出通道使 GEMM 的 K 维只有 9，整段退化为带宽受限；融合内核把 12 个
累加器保持在寄存器里，避免 im2col 的两次全量拷贝。
